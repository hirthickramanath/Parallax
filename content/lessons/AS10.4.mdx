<LessonSection id="ready" title="Before you start" layer="before">

Read the linked prerequisites and keep a proof notebook. State the domain, assumptions and units before using any formula. A soft-lock override does not establish prerequisite knowledge.

</LessonSection>

<LessonSection id="puzzle" title="Commit to a prediction" layer="puzzle">

What counts as reproducing a published result rather than merely drawing a similar-looking plot? State a prediction and a reason before reading the argument.

</LessonSection>

<LessonSection id="story" title="Why the question matters" layer="story">

A capstone needs a chosen claim, exact inputs, defined tolerances and a transparent record of differences from the original analysis.

</LessonSection>

<LessonSection id="intuition" title="Build a mental model" layer="intuition">

Start with the concrete worked example below. Track which quantities belong to the system, which are imposed by its surroundings, and which conclusions require a limiting approximation.

</LessonSection>

<LessonSection id="concept" title="Definitions and hypotheses" layer="concept">

A reproduction project specifies a published target and reconstructs its result with traceable data/code/method assumptions, distinguishing reproduction, replication and extension as defined in the project.

</LessonSection>

<LessonSection id="theory" title="Derivation, proof and limitations" layer="theory" fullOnly>

Choose one bounded target such as a table entry, scaling fit or figure panel. Record paper version, data release, preprocessing, model, parameter convention and output definition. A visually similar curve can arise from different units or normalization; compare numerical quantities such as $r=(x_{new}-x_{ref})/\sigma_{ref}$ only when the reference uncertainty and correlation assumptions support that comparison.

Separate a faithful reproduction baseline from changed priors, algorithms or data. An extension may be scientifically useful but does not substitute for demonstrating the original target. Missing proprietary inputs or unavailable calibration can make an exact reproduction impossible; document the limitation rather than silently inventing replacement observations.

Use a clean executable workflow with input checksums, dependencies, seeds and declared tolerances. Validate components on exact or synthetic test cases. Keep a difference log explaining whether mismatches come from data versions, stochastic error, numeric precision or unresolved methodology.

The final report includes claim, assumptions, evidence, uncertainty, reproducibility instructions and remaining discrepancies. No automatic XP or a successful script should be called independent scientific certification. This lesson offers a project rubric and methods; it does not claim that a specific published result has already been reproduced.

</LessonSection>

<LessonSection id="interactive" title="Investigate the claim" layer="interactive">

Write a capstone proposal with one exact target and a data-access/provenance plan. Complete a synthetic control case before real observations. Keep unavailable inputs as explicit blockers, not invented files, and report every departure from the baseline.

</LessonSection>

<LessonSection id="worked" title="A worked argument" layer="worked" fullOnly>

If a hypothetical reference is 10±2 and the reproduced value is 12 with reference uncertainty used for a simple diagnostic, the standardized difference is 1. That number alone is not a complete joint-consistency test if the two analyses share correlated data or have other errors.

</LessonSection>
