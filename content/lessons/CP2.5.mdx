<LessonSection id="story" title="Why the question matters" layer="story">

Versioned code, immutable inputs and environment records make results reviewable. Parallel execution introduces additional costs and nondeterminism that a successful run does not expose.

</LessonSection>

<LessonSection id="intuition" title="Build a mental model" layer="intuition">

Start with the concrete worked example below. Track which quantities belong to the system, which are imposed by its surroundings, and which conclusions require a limiting approximation.

</LessonSection>

<LessonSection id="concept" title="Definitions and hypotheses" layer="concept">

Reproducibility requires enough recorded code, data, parameters, environment and execution provenance to regenerate a specified result within declared numerical tolerances.

</LessonSection>

<LessonSection id="theory" title="Derivation, proof and limitations" layer="theory" fullOnly>

A Git commit identifies tracked source history, not all untracked data, environment variables or external service responses. Record the code revision alongside input checksums, configuration and dependency versions. Keep credentials out of commits and parameter archives. A seed helps reproduce a particular pseudo-random stream but does not control every library, hardware or parallel scheduling difference.

Separate source inputs, derived artifacts and final figures. A scripted pipeline should express dependencies and fail clearly when a required input is missing or a checksum changes. Preserve meaningful logs and units. A notebook with hidden out-of-order state is not equivalent to a clean top-to-bottom execution; restart and execute from a fresh kernel when validating it.

Measure before parallelizing. Amdahl’s law for an idealized workload with parallel fraction p is $S(N)=1/[(1-p)+p/N]$, ignoring communication and scheduling overhead. Actual performance can be limited by memory bandwidth, input/output, load imbalance and synchronization. Scaling a problem size with processor count is a different experiment from strong scaling a fixed workload.

Floating-point addition is not associative, so a parallel reduction order can change low bits. State whether the requirement is bitwise identity or agreement within a justified physical/numerical tolerance. Checkpoint long computations with validated restart data and track resource use. HPC job scripts, containers and compiler flags are provenance artifacts, not proof of scientific correctness or a reason to disable signature/TLS verification.


### Derivation and transfer

Reproducibility needs versioned source, locked dependencies, input provenance, configuration and a record of random seeds where applicable. A Git commit alone does not preserve untracked data, external services or runtime assumptions. Secrets belong in secure configuration, not source history.

Amdahl's ideal speedup is 1/[(1−f)+f/p] for parallelizable fraction f and p workers, ignoring overhead. The display evaluates that bound, not an HPC benchmark. Communication, memory bandwidth and load imbalance can lower actual speedup. A reproducible performance report records hardware and wall-clock measurements.

</LessonSection>

<LessonSection id="worked" title="A worked argument" layer="worked" fullOnly>

With parallel fraction p=.8 and N=4, ideal speedup is 1/(.2+.8/4)=2.5. As N tends to infinity the upper bound is 1/.2=5 before overhead. A four-core run cannot achieve a factor of four under this serial fraction even in the ideal model.
