This is the current status after the first integrated release. It supersedes that release's counts and pending-feature list. It does **not** declare the full research-level course complete.

## Completed in this branch

CH1 gains seven lessons; CH4 covers bonding, CH5 selected inorganic/block chemistry, and CH6 organic foundations. See `content/chemistry-expansion.json` for overlap decisions and application checks.

- Replaced answer-like recall prompts with genuine retrieval questions, and expanded the original lessons' review sets.
- Validated authored prerequisites as well as inventory prerequisites, enforced template order and conceptual-check balance, rejected duplicate/mismatched IDs and invalid answer keys, and required explicit source-review metadata before a verified/published status is accepted.
- Added an MDX authoring guard: literal TeX outside math delimiters cannot accidentally execute as JavaScript. Registered components and MDX source-check comments remain supported.
- The generated tutor content directory removes stale generated lesson files when an authored source is removed. It is not a second independent source of truth.

### Learning tools

- Revision now uses **3–5 distinct authored cards** from the target lesson, with the target concept first and weaker related cards next. The queue is frozen when a session starts, so rating a card cannot reorder or repeat it accidentally. Why and transfer questions must be attempted before finishing; their score is recorded separately from self-rated recall.
- Added a scrollable visual prerequisite map with accessible textual labels, playable/stub distinctions, and FSRS recall estimates. The local author audit can show the full lesson graph.
- Added an exam-date planner at `/revision-plan`. It includes available prerequisite concepts, prioritizes weak/unreviewed material, schedules before the chosen date and saves locally per account. Opening a scheduled concept starts its revision session. It does not postpone or override FSRS due dates.
- Weekly planning now applies a study mix, keeps earlier eligible phases first, groups saved lesson IDs by actual track, avoids duplicates and never assumes that merely planned prerequisites are complete. The balance is a study preference, not a subject-selection feature.
- The Bridge diagnostic now has 20 conceptual and 20 numerical questions. Each five-question skip test contains three conceptual and two numerical items, with 80% still required for credit. These remain draft screening assessments, not a professionally validated JEE-level exam.
- Added per-track XP analysis and an explicitly model-based retention curve. The review forecast uses the learner's timezone and includes overdue cards in today's count.
- Added opt-in in-app and browser-notification reminders **while the website is open**. Permission is requested only by an explicit button. Reminders respect the timezone, daily goal and per-day dismissal. They are **not background Web Push**.
- Added a development-only `/author` audit with source-review flags, question balance, source filenames and graph inspection. Edit MDX in the repository and use Git review; the production site cannot publish content through a browser toggle.

### Actual virtual apparatus

The circuit bench shows an ideal DC supply, a series ammeter, a voltmeter across the load and either series or parallel resistors. Change supply voltage/resistances/topology, record explicitly synthetic meter readings, and compare V/I, branch quantities and power. Changing the load resets the observation table rather than mixing incompatible experiments. The diagram and numerical model use the same circuit topology.

This joins the pendulum apparatus, orbit explorer and earlier intuition demonstrations. Readings are generated by idealized models; none are represented as measurements acquired from real hardware.

### Tutor reliability and storage

- Conversations now have account- and lesson-scoped local persistence, queued cloud writes, and restoration from the existing `users/{uid}/chats/{conversationId}/messages/{id}` schema. Parent conversation creation and child writes use transactions. The interface displays up to 100 recent messages; unsynced older messages are retained until written or a visible storage error occurs.
- Streamed partial replies are saved, cancellation preserves received text, and remaining daily requests are shown when the Worker reports them.
- Added provider connection deadlines, stream deadlines, output/buffer limits, locked-reader cancellation, late-provider stream cleanup, Unicode/chunk-boundary handling and sanitized failures. Token validation now explicitly requires the standard time/subject claims.
- Live tutoring remains disabled. Local tests are not proof of real-provider availability or production Firebase-token verification.

## Deploy this branch

1. Open the supplied GitHub comparison link and create a pull request into `main`.
2. Review and merge it. Cloudflare Pages builds `main` automatically with `npm run build`, output `dist`.
3. Open the deployed site. Check `/learn` shows 354 entries and 15 playable drafts. Try `/lesson/MB3.1`, `/lesson/CB.2` and `/labs` → Circuit bench.
4. For cloud sync, open https://console.firebase.google.com/project/parallax-73/firestore → **Rules**, replace the editor with the complete current `firestore.rules`, and click **Publish**. Do not enable publicly writable test rules.
5. Sign in on the production website, add a notebook entry and check Settings → cloud status. Confirm it appears on another device signed into the same account. Then verify another account cannot read it.
6. Leave live tutoring off until provider eligibility and the Worker setup steps in `INTEGRATED-RELEASE.md` are completed. No AI credential is needed for the rest of the app.

## Reproduce checks

From the repository root, use Node 24 LTS:

```sh
npm ci
npm run build
npm test
npm run test:worker
npm run typecheck:worker
npm run test:browser
```

`npm run build` includes the app TypeScript check, MDX safety checks, quiz/template validation and graph validation. Browser tests run against the production build and cover every authored lesson. The Worker runtime test exercises CORS/missing-auth handling and 75 concurrent counter requests, with exactly 50 accepted. Pure stream tests exercise real ReadableStreams but do not call an AI provider.

For Firestore rules, after the official emulator download is permitted and Java 21 is available:

```sh
npx firebase-tools emulators:exec --project demo-parallax --only firestore "npm run test:rules"
```

That command targets a demo project rather than the production database. Do not count it as passed until it executes.

The dependency audit currently reports zero high/critical findings, two moderate React Router v6 findings and four low maths-rendering/parser findings. The unchanged major-version decision and audit limitations are recorded in the README.
